# 风眼 · Typhoon Eye

> 台风实况信息 + 分级应急预案，一页看懂、照做即可。极简、零依赖的静态单页，与 [蛛网之上](https://github.com/Mr-Salticidae/above-the-web) 同源的纸墨设计体系。

**在线访问：https://mr-salticidae.github.io/typhoon-eye/**

**⚠️ 本站为信息聚合与科普工具，非预警发布渠道。防灾决策请以当地政府与气象部门发布的官方预警为准。**

## 功能

- 🌀 **实况面板** — 台风位置、风力、气压、移向移速、风圈半径（实时数据）
- 🌧️ **雨情面板** — 并列呈现台风影响范围内的暴雨 / 山洪 / 地质灾害预警，按省聚合并标出最高档位
- ⏳ **影响持续期** — 台风停编后不立即归零：影响省份仍有洪涝预警在效时，页面保持风险姿态而非"风平浪静"
- 🔍 **多源交叉校验** — 中央气象台 / 浙江台风路径系统 / 日本气象厅（JMA）三源比对，页面明示一致性与各源时次
- 🗺️ **路径示意图** — SVG 历史/预报路径，视窗随路径动态扩展，逐点悬停查看强度
- 🌏 **远洋视图** — 台风生成于西北太平洋远洋（海岸线外）时自动切换：经纬网定位 + 可缩放小地图（全球 / 亚太 / 西北太平洋三档），框出当前图幅在地球上的位置
- 🚦 **四级预警** — 蓝/黄/橙/红切换，按「风力档」与「洪涝预警档」的**较高者**预选参考档位，颜色对齐官方预警信号
- ✅ **分级预案** — 递进式可勾选行动清单，进度自动保存
- 🧭 **地区化预案** — 手动多选沿海、海岛、低洼城区、山区河谷、江河湖库、内陆乡村等风险场景；不请求 GPS、IP 定位或精确地址，地区选择不保存、不上传
- ☎️ **应急信息** — 求助电话与权威信息源直达
- 🌗 **昼夜双主题** · 多台风并存时可切换 · 无台风时预案常备

## 数据

GitHub Actions 每 15 分钟运行 [`scripts/fetch-typhoon.mjs`](scripts/fetch-typhoon.mjs)（主任务 + 守护任务共 8 个触发点/小时，抵御 GitHub 调度偶发丢班），并行抓取三个官方源生成静态 [`data/typhoon.json`](data/typhoon.json)：

| 源 | 角色 |
| --- | --- |
| [中央气象台](http://typhoon.nmc.cn/web.html) | 主源：轨迹与实况优先采用 |
| [浙江省台风路径实时发布系统](https://typhoon.slt.zj.gov.cn/) | 备源：主源缺失时出轨迹 + 交叉校验 + 风圈补全 |
| [日本气象厅 JMA](https://www.jma.go.jp/bosai/map.html#contents=typhoon) | 交叉校验 + 国际命名权威（任一源率先命名即采用，JMA 英文名经命名表对照中文名） |
| [中央气象台预警发布平台](http://www.nmc.cn/publish/alarm.html) | 暴雨 / 山洪 / 地质灾害 / 台风预警，驱动雨情面板与预案档位 |

跨源按国际编号（未命名系统按中心距离）匹配同一台风，比对定位与强度并按各机构时次差放宽容差；结果连同各源状态写入 JSON，页面明示"多源校验一致 / 存在分歧 / 单源跟踪"。客户端并行请求 Pages 与 jsDelivr 多镜像（Actions 更新后主动清理 jsDelivr 缓存），取最新数据；全部失败时依次降级为包内缓存和内置演示数据，并显著标注当前数据状态。

小地图底图 [`assets/basemap.js`](assets/basemap.js) 由 [`scripts/build-basemap.mjs`](scripts/build-basemap.mjs) 离线生成一次（Douglas–Peucker 抽稀后内嵌为静态坐标，15 KB，运行时零依赖），数据源为 [Natural Earth](https://www.naturalearthdata.com/) 1:110m Land（public domain）。只含陆地轮廓、不含任何国界线；南海诸岛与九段线由页面内专门插图表达。

## 为什么并列雨情

台风等级只反映**风速**，不反映致灾程度。2026 年第 10 号台风美莎克（MAYSAK，2610）是一次代价惨重的验证：

- 它 7 月 3 日以强热带风暴级登陆海南陵水，7 月 4 日在越南广宁芒街二次登陆，**始终没有升格为台风级**；
- 登陆后结构不但没垮，反而在陆上重建眼区，眼区凌晨经广西东兴入境，随后**在广西内陆滞留 26 小时**；
- 极端降雨引发六蓝、云表等水库溃坝。截至 8 月 21 日，南宁、贵港两地**遇难 159 人、失联 10 人**，其中水库溃坝洪灾遇难 107 人。官方将其定性为"**弱级强灾**"。

对照当时风眼的逻辑：预警档位由 `windLevel` 单独决定。美莎克登陆时 10 级 → 黄色；减弱为热带低压后 → **蓝色，四档中的最低档**，而那正是伤亡最集中的时段；7 月 7 日停编后台风从数据中消失，页面回落到"风平浪静"，而遇难数字在此后六周里从 39 升至 159。

所以本项目做了三处结构性修改：

1. **雨情与实况并列**，而不是作为风力统计的附注；
2. **档位取「风力档」与「洪涝预警档」的较高者**，风力不再单独决定档位；当洪涝档高于风力档时，页面显式标注"台风等级只反映风速，不代表致灾程度"；
3. **停编不等于归零**，保留最长 7 天的影响持续期，其间只要影响省份仍有洪涝类预警在效，就维持风险姿态。

预警与台风的关联有两条规则：该省气象台已发布台风预警（官方口径，多台风并存时按最近者归属，距离上限 1500 km），或省中心距该台风实况点/预报路径 ≤450 km。**这是"台风↔省份"的关联，与用户位置无关**——风眼依然不请求 GPS、不推断 IP 位置、不询问住址。


## 隐私边界

- 不请求浏览器定位权限，不读取 GPS，不通过 IP 推断位置，也不要求填写省市、住址或精确地址；
- 地区化预案采用用户主动选择的公开风险场景，选择与对应清单进度只存在当前页面内存中，刷新即清空；
- 仅主题偏好与全国通用清单勾选进度保存在浏览器 `localStorage`，不会上传到服务器；项目不含账号系统与分析埋点。
- 本项目没有服务端用户数据库；和其他静态网站一样，页面资源请求仍会由 GitHub Pages、jsDelivr 等托管服务按其隐私政策处理，但项目不会用这些请求做用户定位或建立位置档案。

## 使用

无需构建，克隆后直接双击 `index.html`（离线降级演示模式），或本地起静态服务器后访问以加载真实数据：

```bash
npx serve .
```
